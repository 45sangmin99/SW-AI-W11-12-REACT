# Mini React — 요구사항 정의서 (v13, 원문 기준)

> 이 문서는 과제 원문에 적힌 내용만 요구사항으로 옮긴 것이다.
> - 모든 항목에 원문 줄 번호를 `(L00)`으로 표기한다.
> - 원문에 없는 설계 결정, 추가 기능, 해석은 넣지 않았다.
> - 원문이 정하지 않아 구현하면서 정해야 하는 부분은 요구사항이 아니라 **8장 목록**으로만 둔다.

## 2. Phase 1 — Virtual DOM · Diff · Patch

| ID | 요구사항 | 확인 방법 | 원문 |
| --- | --- | --- | --- |
| P1-01 | 브라우저의 DOM 정보를 읽어서 Virtual DOM으로 변환하는 함수를 작성한다 | DOM을 넣으면 그 구조를 담은 Virtual DOM이 반환된다 | L17 |
| P1-02 | 두 Virtual DOM을 비교하여 변경된 부분을 찾아내는 Diff 알고리즘을 작성한다 | 두 Virtual DOM을 넣으면 변경된 부분이 반환되고, 같으면 변경이 없다 | L19 |
| P1-03 | 변경된 부분만 실제 DOM에 반영한다 (Patch) | Patch 후 변경되지 않은 부분은 그대로 유지된다 | L43, L113 |

| P1-17 | Diff 알고리즘으로 이전 Virtual DOM과 비교하여 변경된 부분을 찾는다 | Patch 시 이전 Virtual DOM과의 변경 목록이 만들어진다 | L41 |

| P1-21 | 앞으로가기 버튼으로 State History에 저장된 Virtual DOM으로 이동하며, "실제 영역"과 "테스트 영역"이 함께 변경된다 | 뒤로가기 후 앞으로가기 시 두 영역이 원래 내용으로 돌아온다 | L47 |

## 3. Phase 2 — Component · State · Hooks

### 3.1 Component

| ID | 요구사항 | 확인 방법 | 원문 |
| --- | --- | --- | --- |
| P2-01 | Component는 UI를 나누는 작은 단위이다 | UI가 여러 Component로 나뉘어 있다 | L54 |
| P2-02 | 각각의 Component는 자신만의 로직과 렌더링을 담당한다 | 각 Component가 자기 부분의 화면을 만든다 | L56 |
| P2-03 | 반드시 함수형 컴포넌트로 구현한다 | 모든 Component가 함수다 | L58 |
| P2-04 | 함수형 컴포넌트를 감싸는 `FunctionComponent` 클래스를 직접 만든다 | `FunctionComponent` 클래스가 있다 | L62 |
| P2-05 | `FunctionComponent`는 **hooks 배열**(상태 저장용)을 가진다 | 인스턴스에 hooks 배열이 있다 | L64–66 |
| P2-06 | `FunctionComponent`는 **`mount()`**(처음 렌더링)를 가진다 | `mount()` 호출 시 화면에 처음 렌더링된다 | L68 |
| P2-07 | `FunctionComponent`는 **`update()`**(상태 변경 후 다시 렌더링)를 가진다 | 상태 변경 후 `update()`로 다시 렌더링된다 | L70 |

### 3.2 제약조건

| ID | 제약 | 원문 |

## 8. 원문이 정하지 않은 사항 (요구사항 아님)

원문에 기준이 없어서 구현하면서 팀이 정해야 하는 부분이다. 여기서는 **목록만** 두고 답을 정하지 않는다. 정한 내용은 구현 결과로 설명할 수 있으면 된다.

| # | 원문이 정하지 않은 것 | 관련 원문 |
| --- | --- | --- |
| U-01 | Virtual DOM 객체의 구조 | L17, L146 |
| U-02 | 테스트 영역에서 HTML을 수정하는 방식 (코드 편집 칸, 직접 편집 등) | L35 |
| U-03 | "5가지 핵심 케이스"가 무엇인지 (원문은 목록을 주지 않음) | L154 |
| U-04 | 첫 버전에서 뒤로가기, 마지막 버전에서 앞으로가기를 누를 때의 동작 | L47 |
